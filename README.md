## Лабораторна робота №3 — каталог товарів

У `Lab03-Products` реалізовано список товарів за адресами `/products` та `/items`, перегляд товару, створення, редагування й видалення. Список можна фільтрувати через query string за назвою, категорією та діапазоном цін. Для відсутнього ID показується власна сторінка 404.

Адміністративний список доступний за `POST /users/index`, коли параметр `parameter` у тілі запиту має правильне значення. Значення не передається в URL; без нього сервер відповідає `401 Unauthorized`.

### Запуск

```powershell
cd Lab03-Products
dotnet run
```

Приклади сторінок:

- `/products/index?category=Drinks&maxPrice=10` — список із фільтрами.
- `/products/1` — інформація про товар.
- `/products/edit/1` — редагування товару.
- `/products/delete/1` — підтвердження видалення.
- `/products/create` або `/products/new` — створення товару.

## Лабораторна робота №4 — валідація та model binding

`Lab04-ValidationBinding` продовжує застосунок із лабораторної №3 в окремому проєкті. Тут додано перевірки ціни, назви й опису товару та вибір типу (`Toy`, `Technique`, `Clothes`, `Transport`). Також можна змінити ціни всіх товарів обраної категорії одним поданням. ID і назви в цій формі доступні лише для читання.

Товар зберігається й відкривається в режимі перегляду, якщо введені дані валідні; інакше помилки відображаються на тій самій формі.

Користувача можна створити лише через query string, наприклад `/users/create?name=New%20User&email=new.user%40example.com`. Поля на формі лише для читання; кнопка **Save user** додає користувача й показує його сторінку.

Приклади нових сторінок лабораторної №4:

- `/products/edit-prices/Toys` — масове редагування цін у категорії `Toys`.
- `/users/create?name=New%20User&email=new.user%40example.com` — форма створення користувача з даними з query string.

### Запуск лабораторної №4

```powershell
cd Lab04-ValidationBinding
dotnet run
```
